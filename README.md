# 太上感應篇｜互動電子書

《太上感應篇》（道教勸善書，託名太上老君，全文 1,277 字）的網頁電子書：原文、白話、註解、朗讀，加上幾種取自原文的互動。蔬米 OMILKYWAY「經典互動」系列之一，和《十善業道經》電子書、弟子規小遊戲、三款遊記遊戲同一個家族；程式是從《十善業道經》那一本（`ten-virtues-sutra`）改寫來的。

正式網址：<https://edu.omilkyway.org/taishang-ganying-pian/>

## 這本書有什麼

- **十章、13 頁**：依清代《太上感應篇直講》的分章——明義、示警、鑑察、積善、善報、諸惡、惡報、指微、悔過、力行。〈諸惡章〉最長，分成四頁。原文一字不漏，每段有白話，難詞可以點開看註解，每頁可以朗讀。
- **112 盞燈**：〈積善章〉的 22 條善行一句一盞（金燈）；〈諸惡章〉的 90 列（多半是對句）一列一盞（銀燈：看清一條過失）。點了才亮、才顯示白話。
- **生活情境題**：每頁一題，三個選項，選完給回饋，不計分。
- **善惡對照**：〈積善章〉的一條善行 ↔〈諸惡章〉裡和它相反的一句（《直講》說「眾善之細目，即具在諸惡之對面」）。
- **轉禍為福**：一幅畫被十片烏雲蓋住，圓滿一章就散開一片。有燈的章要全部點亮；沒有燈的章，讀過就算。
- **每日三善**：對應結尾的「語善、視善、行善，一日有三善」，每天三項自我檢核，並累計做了幾善（原文的「三百善」「一千三百善」）。
- **點圖放大**：封面和各頁插圖點一下就全螢幕看完整的圖，點任意處、✕、Esc 或手機返回鍵關閉。「轉禍為福」要十片烏雲都散開之後才能放大。
- **注音**：每頁「經文」標題列有一顆「注音：關／開」，和「朗讀」「白話」放在一起；預設關。打開後原文每個字的右邊顯示直式注音（課本那種排法；白話、註解、情境題不加），換頁、重開都記得。

進度只存在讀者自己的瀏覽器裡（`localStorage`，鍵 `ganyingBook.v1`、`ganyingDaily.v1`），沒有帳號。「顯示注音」的開關另外存在 `ganyingPrefs.v1`，「清除閱讀進度」不會動到它。

**Google Analytics：** 2026-11-19 裝上，評估 ID 是 `G-1Y2K10ZCPL`（GA 帳戶 OMILKYWAY.ORG 底下的資源 `taishang-ganying-pian`；這個系列各作品的資源都放在這個帳戶）。評估 ID 寫在 `js/config.js` 的 `GA_MEASUREMENT_ID`，Google 代碼在 `index.html` 的 `<head>`，兩邊要一起改，`tests/html.test.js` 會檢查一致；「關於本書」有 ID 才會多一句說明。翻頁時 `js/app.js` 會自己送 `page_view`（標題是章名，網址用路由當路徑，例如 `…/taishang-ganying-pian/ch/4`），GA 的「網頁和畫面」報表才看得出各章的閱讀量。

## 部署

整個資料夾就是純靜態網站，沒有建置步驟。GitHub Pages 設定為 `main` 分支根目錄，push 之後自動發布。

換網址時要改兩處：`js/config.js` 的 `BOOK_URL`，以及 `index.html` 的 `og:url`、`og:image`（`tests/html.test.js` 會檢查兩邊一致）。

## 內容慣例（測試會守門）

- **原文不能動。** 所有 `raw` 依序串起來、去掉空白之後，必須和 `tests/fixtures/ganying-pian.txt` 逐字相同，標點也算（`tests/fidelity.test.js` 會指出第幾個字不同）。去掉標點後是 1,277 字，和 `tests/fixtures/ganying-pian-wikisource-bare.txt`（維基文庫通行本）只差三個異體字的寫法。
- **白話、註解、情境題都是自己寫的**，不轉載別人的譯本。句子的意思依據清代的《太上感應篇集註》和《太上感應篇直講》（都是公有領域，維基文庫有全文），並參考《正統道藏》本的李昌齡傳，以及行天宮編譯的《太上感應篇》（有著作權，只拿來核對意思，不抄它的句子）。
- 原文是在「描述一種行為」，白話就照樣描述，不改成命令句、不加評論。講神明與報應的地方照原文平實翻譯，不加油添醋、不引註解裡的報應故事、不寫嚇人的細節。不貶其他信仰，不寫療效。
- 帶著時代背景的句子（家庭裡的尊卑、良賤身分、對星辰與灶的禁忌、墮胎等），白話照翻，另外用 `note` 一句話交代背景；語氣平實，不批判古人、不替古人辯護、不羞辱任何人，用詞要適合親子共讀。
- 原文的「常」是「總是、一再」，白話不要寫成「常常」。
- 區塊的 `terms` 引用 `glossary.json` 的鍵，那個詞必須真的出現在該區塊的 `raw` 裡；沒有被引用的詞條不能留。同一個字在不同地方意思不同時，開不同的鍵。註解裡的注音，沒有十足把握的不要寫。
- 清單超過 12 列時要分組，同一組的每一列都寫相同的 `group`。
- `match.json` 每一組的兩句都必須是原文裡的句子。

## 原文的底本

- 底本是通行本：維基文庫《太上感應篇》，和清康熙四十五年（1706）《太上感應篇集註》所錄的正文相同，共 1,277 字。
- 三個異體字改用教育部的標準字：竈→灶（4 處）、鬪→鬥（1 處）、鑒→鑑（1 處）。
- 新式標點和分段是本書自己加的。全篇不加引號（「太上曰」之後到哪裡為止，各家讀法不同）。
- 做書時對校過四個本子：通行本、《集註》逐句標題、《直講》、《正統道藏》本（李昌齡傳）。較明顯的異文：「惟人自召」道藏本作「唯」；「以當妄取之值」道藏本、《集註》《直講》作「直」；「見他色美」《集註》《直講》作「美色」；「呵風罵雨」三本作「訶」；「知善不為」《直講》作「見善不為」；「以害民居」《直講》、道藏本作「居民」；行天宮本另有「三台北斗星君」「有數萬事」「天地佑之」幾處不同。本書一律從通行本，個別地方在註解裡說明。

## 注音

`js/data/zhuyin.json` 是全文 568 個不同的字的讀音，分三部分。`chars` 和 `poly` 分開放，是為了一眼看得出哪些地方是人工判斷：

```json
{
  "chars":   { "太": "ㄊㄞˋ", … },
  "poly":    { "惡": "ㄜˋ", "好": "ㄏㄠˇ", … },
  "phrases": { "人皆惡之": "ㄖㄣˊ ㄐㄧㄝ ㄨˋ ㄓ", "好侵好奪": "ㄏㄠˋ ㄑㄧㄣ ㄏㄠˋ ㄉㄨㄛˊ", … }
}
```

- `chars`：單音字（辭典只列一個讀音），404 個，直接用辭典的讀音。
- `poly`：破音字（辭典列出兩個以上讀音），164 個。這裡寫的是**辭典列的第一個讀音**（《簡編本》的 (一)；《簡編本》沒收的字用《重編》的第一個），不一定是本文用到的讀音。
- `phrases`：本文裡**不讀第一個讀音的每一處**，也就是全部的人工判斷。鍵是原文裡連續的幾個字（要在同一段或同一列之內，不含標點），讀音用空白分開、一字一音。標音時詞句優先於單字，長的詞句優先於短的。

讀音的依據與慣例：

- 以臺灣教育部的標準為準，不用大陸的普通話讀音，也不拿拼音工具轉換（危ㄨㄟˊ、識ㄕˋ、穴ㄒㄩㄝˋ、暫ㄓㄢˋ、辱ㄖㄨˋ、偽ㄨㄟˋ 這類字兩岸不同）。查兩部辭典：《國語辭典簡編本》（依《國語一字多音審訂表》，現行教學用的標準讀音）和《重編國語辭典修訂本》（古義、讀音／語音／又音都收）。
- 《簡編本》只列一個讀音的字就用那個讀音，不另外採用《重編》保留的又音、讀音。破音字依文意判斷，參考兩部辭典的釋義和例詞，以及清代《直講》的直音（「降，音祥」「號，音豪」）。
- 一聲不標調；二三四聲的調號寫在後面；輕聲的「˙」寫在前面。全篇是文言，不標輕聲（「妻子」是妻和子，讀ㄑㄧ ㄗˇ）。「一」「不」照課本標變調（一日ㄧˊ、一千ㄧˋ、不當ㄅㄨˊ）：資料和 `annotate()` 仍是本調，顯示時才由 `applySandhi()` 換掉，辭典查證用的也是本調。
- 註解（`glossary.json`）裡寫了注音的字，同一處的注音必須一樣（`tests/zhuyin.test.js` 會比對）。
- 有三個字的讀音不在自己的辭典條目底下，是依異體字或通假採用的：三台的「台」讀ㄊㄞˊ（「臺」的異體字）、穢食餧人的「餧」讀ㄨㄟˋ（「餵」的異體字）、埋蠱厭人的「厭」讀ㄧㄢˇ（通「魘」，《直講》：「厭，音掩」）。
- 2026-11-19 和行天宮編譯的《太上感應篇》（書末附注音全文）逐字比對過，只有七處不同，由書的主人逐條定案。**改從行天宮本的三處**：懷挾外心的「挾」ㄒㄧㄝˊ（也是《重編》的正讀）、虛誣詐偽的「誣」ㄨˊ（《重編》的讀音）、春月燎獵的「燎」ㄌㄧㄠˋ。**維持不跟的四處**：埋蠱厭人的「厭」ㄧㄢˇ（行天宮ㄧㄢˋ）、無行於妻子的「行」ㄒㄧㄥˋ（行天宮ㄒㄧㄥˊ）、橫取的「橫」ㄏㄥˋ（行天宮ㄏㄥˊ）、裸露的「露」ㄌㄨˋ（行天宮ㄌㄡˋ）。這七處都由 `tests/zhuyin-sandhi.test.js` 釘住，不要再照辭典改回去。陰賊良善的「賊」ㄗㄟˊ兩本相同（《重編》另有ㄗㄜˊ）。

查證用 `scripts/zhuyin-check.mjs`。它把全文每個不同的字逐字到兩部辭典查出所有讀音，存成快取（`content-src/zhuyin-dict/`，不進 repo），再檢查 `zhuyin.json`：

```bash
node scripts/zhuyin-check.mjs fetch    # 只查還沒查過的字（一次一個字、慢慢查；全部重查約二十分鐘）
node scripts/zhuyin-check.mjs          # 檢查：每個字都標到音、選的讀音都在辭典列的讀音裡、chars／poly 沒放錯邊
node scripts/zhuyin-check.mjs --list   # 另外印出破音字清單：每一處的句子、選的讀音、兩部辭典列的讀音和釋義
```

標了「請人工確認」的幾類不算錯，但改動後要再看一眼：依異體字或通假採用的讀音、《簡編本》只列一個讀音而這裡選了別的、和《簡編本》收的詞讀音不同的（同樣幾個字在文言裡可能是別的意思）。改了原文或 `zhuyin.json` 之後，先跑 `fetch` 再跑檢查；要重查某個字，把快取裡那個字的檔案（檔名是它的 Unicode 碼位）移走再跑 `fetch`。

畫面上，注音只在「注音：開」時才畫：`js/ui/gloss.js` 把原文的每個漢字換成 `<ruby>字<rt>注音</rt></ruby>`，標點不動，難詞的 `<span>` 還是原來那一個（事件和展開狀態不受影響）；關掉就換回純文字。`zhuyin.json` 讀不到時書照樣能讀，只是沒有這顆開關。

排法是臺灣課本的**直式注音**：注音排在字的右邊，聲母、介音、韻母由上往下疊成一欄，整欄相對於字垂直置中；二三四聲的調號在最後一個符號的右上方，輕聲的點在這一欄的最上面，一聲不標。資料的寫法（輕聲寫在前、調號寫在後）不變，顯示時才拆開（`js/zhuyin.js` 的 `splitSyllable`）：

```html
<ruby>你<rt><span class="zy-col"><span>ㄋ</span><span>ㄧ</span></span><span class="zy-tone">ˇ</span></rt></ruby>
```

- 不用 `ruby-position: inter-character`（Chrome 不支援），是自己排的（`css/style.css` 的「注音」）：字還是行內的普通文字，右邊用 padding 空出一欄，`<rt>` 絕對定位貼在那一欄裡。注音不佔行內的位置，所以斷行和沒有注音時一樣——字和它的注音拆不開，標點也不會跑到行首。`ruby` 上的 `white-space: nowrap` 不能拿掉，少了它 Chrome 會把行尾那個字的注音甩到下一行。
- 注音的字級是字的 0.34 倍，三個符號疊起來大約一個字高。開注音時原文放大到 1.5rem，不然注音太小看不清楚。
- 注音用系統內建的字型，不載外部字型。
- 開著注音時複製原文，瀏覽器會在每個字後面多塞一個換行（注音欄是區塊）；`chapterView.js` 在複製的那一刻先把注音藏起來再取文字，貼出去的是乾淨的原文。
- 朗讀唸的是資料裡的原文（`chapterRaw`），不讀畫面上的字，所以不會把注音唸出來。
- 這些排版 happy-dom 量不出來（它不排版）。改了注音的 CSS，要在真的瀏覽器、390px 寬逐頁看過：字和注音有沒有被拆到兩行、行首有沒有標點、調號有沒有壓到下一個字、有沒有橫向捲軸。

## 插圖

15 張（封面＋13 頁各一張＋「轉禍為福」的整張大圖），用 gpt-image-2 生成。提示詞在 `scripts/art-prompts.mjs`，每張都以同一段風格前綴開頭（台灣廟宇彩繪、Q 版人物、多色且冷暖均衡、主角畫得大放前景、遠景小人最多兩三個、畫中不得有字）；反覆出現的太上老君和兩個孩子寫成固定的描述，各張才會長得一樣。

```bash
node scripts/gen-art.mjs                 # 補齊 art-src/ 裡還沒有的圖
node scripts/gen-art.mjs c04-good-deeds  # 只重畫指定的圖
node scripts/contact-sheet.mjs           # 拼成對照表過目（art-src/_preview/）
npm run opt-art                          # art-src/*.png → assets/art/*.webp，並由封面產生 assets/og.png
```

`art-src/` 是原圖，不進 repo。新增一張圖要同時改三處：`scripts/art-manifest.mjs`、`scripts/art-prompts.mjs`、`chapters.json` 的 `art`；換了圖要記得改 `chapters.json` 的 `alt`（封面和「轉禍為福」的 alt 在 `js/config.js`）。
